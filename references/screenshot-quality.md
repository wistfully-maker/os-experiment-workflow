# 截图质量规范（真实终端 + 无空白）

本文件是实验报告**截图环节的质量标准与自检清单**，与执行环境无关。
Linux VM 的连接参数、X11/xterm 细节见 `environments/linux-vm-ssh.md`。

---

## 一、核心原则：截图必须是"真实终端产生的"

> 一份截图的观感好坏，往往决定了老师对整份报告的第一印象。
> **"看着假"的截图比"不好看"的截图更致命** —— 它会让评阅人怀疑实验是否真的做过。

### 1.1 三条硬标准

| # | 标准 | 判定方法 |
|---|------|----------|
| 1 | 提示符由 shell 自己输出 | 提示符必须来自 PS1，不能是脚本 `echo` 出来的文本 |
| 2 | 命令由终端回显 | 命令应出现在提示符之后、与输出同一屏，且**没有输出的命令也要能看到命令行** |
| 3 | 输出与提示符自然交错 | 提示符 → 命令行 → 输出 → 下一个提示符，逐条推进 |

### 1.2 "看着假"的典型特征（自检）

| 表现 | 根因 |
|------|------|
| 提示符与输出**字体样式完全一样**、无光标感 | 提示符是 `echo` 打出来的普通文本 |
| 一整屏内容**同时出现**，没有逐条推进的节奏 | 命令是脚本批量执行后一次性刷出 |
| `mkdir`、`docker tag`、`systemctl start` 等**没有输出的命令看不到命令行** | 用管道定时喂命令，命令行被下一个提示符覆盖 |
| 提示符连续堆积成 `# # # #` | 管道喂入与 bash 提示符输出存在竞态 |
| 首行不是提示符 | 输出超出窗口行数，开头的命令被滚出画面 |
| 底部一大片空黑/空白 | 窗口行数远大于命令实际输出行数 |

### 1.3 正确做法 vs 错误做法

**❌ 错误：手工画提示符**

```bash
# 命令脚本长这样 —— 一眼假
echo "[root@master ~]# systemctl enable docker"
systemctl enable docker
```

**❌ 错误：管道定时喂命令**（存在竞态，且无输出命令的命令行会丢失）

```bash
( while read -r l; do printf '%s\n' "$l"; sleep 0.8; done < cmds ) \
    | script -q -c "bash -i" /dev/null
```

**✅ 正确：`expect` 驱动真实交互式 bash**

```tcl
spawn bash -i
expect -re {\[root@[^\]]*\]# $}
while {读入一行命令} {
    send -- "$line\r"
    expect -re {\[root@[^\]]*\]# $}     ;# 等提示符返回，保证本条已落屏
}
```

现成的实现见 `scripts/vm_shot.sh`（已封装环境唤醒、会话解锁、日志留存、清理）。

> **命令脚本里只写真正的命令，不要写任何 `echo` 提示符。**
> 提示符与命令回显全部由真实终端产生，画面里没有任何一个像素是后期绘制的。
>
> 唯一"非人为"之处：按键由程序注入而非手敲。但终端本身无法区分二者，
> 渲染路径完全相同。（如需极致真实，可用 expect 逐字符发送并加随机延迟，
> 但对静态截图而言效果没有区别。）

## 二、截图流水线（四步）

```
① 环境就绪   唤醒屏幕 + 解锁会话
      ↓
② 真实执行   expect 驱动 bash，逐条执行命令脚本
      ↓
③ 窗口截图   gnome-screenshot -w（尺寸恒定，不受其它窗口干扰）
      ↓
④ 裁剪       统一宽度 + 紧贴内容
```

### 步骤 ①：环境就绪（最容易漏，漏了就白截）

| 问题 | 现象 | 处理 |
|------|------|------|
| 屏幕被 DPMS 关闭 | 截图**纯黑** | `xset -dpms; xset s off; xset dpms force on` |
| 会话被锁 | 截图是**蓝色时钟锁屏页** | `loginctl unlock-session <SID>`（免密码） |
| 字体缺 CJK 字形 | 中文变**方块** | 选带 CJK 的等宽字体；纯英文输出可用 `DejaVu Sans Mono`（更像真终端） |
| 残留上一次的终端 | 截到旧窗口 | 截图前后各 `pkill -f "xterm .*REPORT_SHOT"` |

### 步骤 ②：真实执行

见 §一。要点：**expect 等提示符返回** + **轮询 done 标记等命令真正跑完**。

> ⚠️ 慢命令（`yum install` 可能数分钟）绝不能"启动后固定 sleep 几秒就截"，
> 会截到命令执行的中间状态。让命令脚本结束时 `touch` 一个标记文件，外层轮询它。

### 步骤 ③：窗口截图

| 方式 | 优点 | 缺点 |
|------|------|------|
| 全屏截图 | 简单 | 含大量桌面空白；**桌面其它窗口会混进画面**；尺寸随分辨率变 |
| **窗口截图 `-w`** | 尺寸恒定、不受其它窗口干扰 | 多出标题栏，裁剪时去掉 |

Linux VM 上 `gnome-screenshot -w -f out.png` 即可，标题栏高度实测固定 **37px**。

### 步骤 ④：裁剪

| 策略 | 命令 | 结果 | 适用 |
|------|------|------|------|
| **统一尺寸** | `--rect "l,t,r,b"` | 所有图完全同尺寸 | 任务书明确要求"尺寸统一"时 |
| **统一宽度 + 紧贴内容** | `--skip-top 37 --margin 8 --uniform-width` | 宽度一致、高度随内容 | **推荐**：既不留空白，又保证各图缩放后文字大小一致 |
| 完全紧贴 | `--skip-top 37 --margin 8` | 宽高都随内容 | 非报告用途（如文档插图） |

> **为什么推荐"统一宽度 + 紧贴内容"**：报告里所有图都会缩放到同一显示宽度
> （如 5.5 英寸）。若各图**原始宽度不同**，缩放后的**文字大小就会不一致**，
> 看上去很别扭；若**高度也统一**，短图底部就会留一大片空白。
> 宽度锁死 + 高度紧贴，同时避开这两个问题。
>
> ⚠️ 与任务书"截图尺寸要大小统一"存在轻微出入，**需与用户确认取舍**。
> 两种裁剪可用同一批原图产出，**不需要重新截图**。

## 三、行数预算

窗口几何的行数 = 一屏可见行数（含最后的光标行），因此：

**命令脚本的输出必须 ≤ 窗口行数 − 1 行**

超出 1 行 → 最早的命令被滚出画面，截图里就看不到"执行了什么"。
**这个坑很隐蔽：日志文件里一切正常，只有看截图才发现。**

建议把每个脚本控制在**窗口行数 − 6 ~ 窗口行数 − 2** 之间：
既不溢出，也不在底部留大片空白。

控制手段：

| 手段 | 适用场景 |
|------|----------|
| `\| tail -N` | `yum install` 装包列表、`docker pull` 分层进度等长输出 |
| `\| grep -v '^$'` | 去掉空行（如 `docker version`） |
| `\| head -N` | 只要开头若干行 |
| `-q` | 让 yum 静默（`yum -q makecache fast` 实测零输出） |
| 补一条真实验证命令 | 输出太短的步骤，加 `docker images` / `docker system df` / `rpm -q` 等，比留白更好 |

**极端情况**：控制不住的长输出（如 PackageKit 抢锁刷出的等待提示）应优先**消除根因**，
而不是加 `grep` 过滤掉——过滤会掩盖真实问题。

## 四、QC 自检清单

截图采集完成后，**先做机器可查的检查，再看图**：

- [ ] 用缩略图总览一眼扫过全部截图：无全黑、无锁屏页、无空桌面
- [ ] 每张图**首行是提示符**（不是输出内容）→ 说明没有滚屏
- [ ] 每张图的**内容行数**在预期区间内（不溢出、不留大片空白）
- [ ] 尺寸：宽度是否全部一致；高度是否都在合理区间
- [ ] 中文是否正常显示（若输出含中文）
- [ ] 终端风格统一（同一字体、同一配色、同一窗口几何）

生成缩略图总览的做法：把所有截图按同一缩放宽度拼成网格 PNG，一次性目视核对。

## 五、故障速查

| 现象 | 根因 | 解决 |
|------|------|------|
| 截图纯黑 | DPMS 关屏 | `xset dpms force on` |
| 截图是锁屏页 | 会话已锁 | `loginctl unlock-session <SID>` |
| 提示符堆积 / 回显丢失 | 管道喂命令存在竞态 | 改用 **expect** |
| 无输出命令看不到命令行 | 同上 | 改用 **expect** |
| 提示符显示 `/home/xxx` 而非 `~` | shell 的 cwd 不是 HOME | 启动前 `cd <用户家目录>` |
| 中文变方块 | 字体缺 CJK 字形 | 换带 CJK 的等宽字体 |
| heredoc 渲染错乱（`> > > >`） | 多行输入与 PS2 提示符交互异常 | 写文件用逐行 `echo ... >` / `>>` |
| 开头命令被挤出画面 | 输出行数超窗口行数 | 见 §三 行数预算 |
| 截到命令执行的中间状态 | 没等命令跑完就截图 | 轮询 done 标记 |
| 裁剪图右侧出现黑带 | `PIL.Image.crop()` 越界会**补黑边**，不会自动裁剪 | 裁剪矩形宽度必须精确等于图片宽度 |
| 各图文字大小不一致 | 各图原始宽度不同，缩放后比例不同 | 用 `--uniform-width` 锁定宽度 |
